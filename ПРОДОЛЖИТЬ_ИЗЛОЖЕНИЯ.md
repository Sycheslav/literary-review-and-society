# Как продолжить подробные изложения

Работа остановлена **29 октября 2026 года по просьбе пользователя из-за остатка лимита**. Новые статьи пока не обрабатывать; продолжать после отдельного запроса пользователя.

## Состояние на момент остановки

- На сайте 281 материал. Подготовлено **107 изложений**: 89 по полным текстам, 9 по документации проектов и 9 ограниченных по доступным источникам. **174 материала остаются без изложения.**
- Все прежние 64 изложения переработаны по единому шаблону. Новые тексты обычно содержат 800–1450 слов, конкретный метод, пайплайн, гипотезы, результаты, ограничения и локаторы оригинала.
- Работает трёхуровневое чтение: карточка/аннотация → `/works/<id>/summary` → оригинал. Есть оглавление, отметка ограниченного источника и прямой переход из графа.
- Полностью завершены пакеты **01–04, 19, 20**. В **05** и **06** готово по 11 из 14 работ. Пакеты **07–18** ещё не завершены; в 07 агент начал чтение, готовые файлы не сохранял. Запущенные агенты остановлены.

## Что читать следующему агенту

1. `AGENTS.md` в корне проекта и главный документ «Социумы ИИ-агентов программа исследований Лаб. 57 ИПУ РАН × «Верхум».md».
2. `content/retellings/TEMPLATE.md` — обязательный шаблон и правила чтения первоисточников.
3. `content/retellings/REMAINING.json` — **точные 174 оставшиеся записи** с названием, ID, URL, путём оригинала и карточки. Этот список важнее старых заданий пакетам.
4. `content/retellings/CHECKPOINT.json` — готовность каждого исходного пакета; `COVERAGE.json` — полный аудит.
5. `content/retellings/NEEDS_ORIGINALS.json` — 9 изложений с ограниченным источником; искать официальные/авторские версии, не выдумывать отсутствующие сведения.
6. `content/retellings/RECOVERY_NOTES.md` и `reports/*.json` — найденные оригиналы, версии и замечания завершённых пакетов.

## Порядок продолжения

Рабочий Git-репозиторий: `C:\PROGA\IPU\Верхум\Литературный обзор граф\site`, ветка `main`, remote `Sycheslav/literary-review-and-society`. Родительский каталог — исследовательский корпус, отдельного Git там нет.

Сначала проверить актуальные Git status, `COVERAGE.json` и наличие файлов: не переписывать уже готовые 107 работ. Закончить остатки 05 и 06, затем выдавать Luna непересекающиеся мини-пакеты примерно по 5 статей из `REMAINING.json`. В этой сессии одновременно доступны три субагента плюс основной агент. Не регенерировать исходные `batches/*.json`: состав каталога и доступность оригиналов уже изменились.

Для каждой работы читать оригинал целиком, существенные приложения и подписи таблиц; старые аннотации и карточки не заменяют оригинал. Результат — `public/corpus/files/materials/<id>/summary.ru.md` и `summary.meta.json`, плюс относительная ссылка из `public/corpus/files/works/<id>.md`. У некоторых оригиналов путь отличается от ID: использовать `textPath`. Сразу сохранять весь комплект по одной готовой статье.

Статусы источника: `fulltext`, `repository`, `limited`. Ограничение доступа не равно отсутствию эксперимента: эссе, документация и институциональный профиль имеют собственный тип. При запрете перераспространения прочитанный оригинал не класть в public; использовать внешний URL и `source_note`. У Centola PDF не опубликован именно по этой причине.

Особенно проверять SD/SE/ДИ, проценты и процентные пункты, условия и знаменатели. В GovSim исправлено ошибочное обозначение SD: подпись Table 1 называет ± доверительным интервалом. В MAST добавлен диапазон 41–86,7% неуспешных решений с границей применимости и ссылкой на рис. 5 приложения B. Не терять эти исправления.

## Проверка и публикация

```powershell
python scripts/build_data.py
python scripts/check_retellings.py
python scripts/sync_retellings_to_corpus.py
npx tsc --noEmit
npm run build
```

`check_retellings.py --require-complete` использовать только после обработки всего каталога: сейчас он закономерно сообщит о неполном покрытии. Предупреждения о компактных README проверены редактором; не раздувать их ради длины. Зеркалирование сохраняет прежние файлы в соседнем `service/cache/retelling-sync-backup-2026-10-29`. `prepare-corpus.mjs` умеет переносить sidecar-метаданные вместе с изложениями.

После проверки коммитить Markdown, метаданные, карточки и пересобранные `data/works.json`, `data/details.json`, затем пушить. **Автодеплой от GitHub не настроен:** у сервиса Railway `source.repo=null`. После пуша нужно отдельно опубликовать код через Railway CLI и дождаться статуса `SUCCESS`.

Для публикации чистого коммита при чужих незакоммиченных изменениях: экспортировать `git archive --format=zip --output=work/release.zip HEAD`, распаковать в новый каталог `work/release` и выполнить `railway up work/release --path-as-root --project 02e74ae8-d0e8-4750-b54d-8deb83be7c1f --environment 69b8c051-49e3-48e2-96af-7592e97a19d5 --service f6bf36e4-af75-4490-b2f6-b5be05a3d949 --detach -m "Описание изменения и хеш коммита"`. Проверять `railway deployment list` с теми же ID. Не заливать рабочий каталог с незавершёнными изменениями другого чата. Проверить опубликованную страницу готового изложения и ограниченного источника.

Во время работы другой чат параллельно добавлял раздел «Экономика»: не откатывать и не включать чужие незакоммиченные изменения без проверки. В общих файлах (`app/globals.css`, карточка работы) отделять свои изменения от чужих. Не выполнять `git add -A` вслепую.
