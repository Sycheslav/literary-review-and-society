## Аннотация

AutoGen — фреймворк для составления LLM-систем из настраиваемых агентов, инструментов и автоматических диалогов.

## Как устроено исследование

README описывает модульную архитектуру: Core API содержит определения агентов, передачу сообщений, событийно-ориентированную локальную и распределённую среду выполнения (runtime), а также поддержку .NET и Python; AgentChat даёт интерфейс, ориентированный на прототипирование, включая двухагентный диалог и групповой чат (group chat); Extensions связывают модельные клиенты (например, OpenAI и Azure OpenAI), исполнение кода и инструменты. AutoGen Studio — графический интерфейс (GUI), AutoGen Bench — набор для оценки. Magentic-One приводится как пример команды, построенной поверх AgentChat и Extensions и способной работать с веб-браузингом, исполнением кода и файлами. Это описание возможностей исходного репозитория (upstream), а не независимый бенчмарк результата.

## Техническая реализация

Репозиторий разделяет Python-рабочее пространство (workspace) на пакеты autogen-core, autogen-agentchat, autogen-ext и autogen-studio. Документация даёт инструменты для заданных ролей и специализаций, маршрутизации сообщений и кода; состав топологии конфигурируется разработчиком. README (просмотрен 27.10.2026) сообщает, что проект «архивирован и более не поддерживается Microsoft»; для новых проектов он рекомендует Microsoft Agent Framework, а AutoGen характеризует как поддерживаемый сообществом (community-managed). Это актуальный статус; не следует отождествлять его с прежней стадией активно развивающегося исследовательского фреймворка (active research framework).

## Промпты и инструкции агентам

Системные сообщения (system messages) и сообщения ролей определяет создатель приложения; общие README и FAQ дают примеры и назначения, но не единый исследовательский промпт. Для анализа социальности необходимо хранить версию шаблона, правила хода, лимиты инструментов и состояние диалога, поскольку фреймворк позволяет это задавать, но не навязывает.

## Результаты подробно

Набор возможностей и границ взят из официальной документации; никакого числа «успешности кооперации» для самого AutoGen карточка не приписывает. Рекомендация перейти на Agent Framework относится к поддержке инструмента, а не к научному сравнению архитектур.

## Выводы авторов

AutoGen полезен как воспроизводимая оркестрационная инфраструктура: он делает видимыми архитектуру сообщений, роли и обмен с инструментами. Для литературы его надо цитировать как программное обеспечение (software), а эмпирические результаты брать из отдельных работ, использующих его.

## Ограничения и интерпретация

Платформа допускает много вариантов архитектуры; результат проекта не задаёт каузального преимущества группового чата (group chat) или конкретной топологии. Текущий репозиторий находится в режиме архива и поддержки сообществом (archive/community maintenance); сохранность, зависимости и различия миграции требуют фиксации коммита (commit) и версии. Агентные «роли» создаются системными сообщениями и не доказывают устойчивые личные свойства.

## Расходы и вычисления

Официальный README не публикует единого бюджета API или стоимости токенов. Расход зависит от подключённого провайдера, модели, длины диалога и вызовов инструментов; здесь он не оценивается.
