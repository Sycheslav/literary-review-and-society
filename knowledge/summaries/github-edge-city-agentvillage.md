# Agent Village at Edge Esmeralda: персональные агенты в человеческом поселении

**Оригинальное название:** AgentVillage. **Авторы:** Edge City / участники проекта. **Год:** 2026. **Тип:** программный пакет и полевая инфраструктура для мероприятия Edge City India (11 октября — 1 ноября 2026, Гоа); не отдельная исследовательская статья. [Официальный репозиторий](https://github.com/Edge-City/agentvillage). Прочитан полный README и относящиеся к нему архитектурные сведения; README сохранён в `readme-source.md`.

## 1. Главный вопрос и ответ

AgentVillage описывает, как дать посетителям временного сообщества персональных агентов на базе Hermes, OpenClaw или Claude, подключённых к общим сетевым сервисам знакомств/поиска контактов и расписанию. Проект интересен как пример живой социально-технической инфраструктуры: агент получает индивидуальный контекст и память, но действует через общие каталоги, события, предложения знакомства и переговоры. README документирует функции и программные механизмы, но не публикует систематических результатов о том, как именно участники или агенты строили отношения.

## 2. Исследовательский вопрос или проектные требования

README не формулирует научные гипотезы. Проектная цель — облегчить установление контактов и участие в поселении при персонализированных интерфейсах. Важное ограничение: социальная координация не свободно возникает с нуля, а направляется задачами платформы, профилями, cron-процессами, предложениями, интерфейсами и разрешёнными интеграциями.

## 3. Агенты, среда и исходные условия

Пакет — навыки и onboarding скрипты; агент подключается через EdgeOS и Index Network. Индивидуальные источники включают идентичность, интересы, память и сообщения жителя; общие службы содержат календарь, справочник, объявления и процедуру обнаружения/согласования контактов. Агент готовит утренний brief в 08:00 IST на основе административных объявлений, календаря и интересов жителя; получает уведомления о принятых контактах, периодически сворачивает дневные заметки в `MEMORY.md`. Есть дополнительные мини-приложения для благодарностей, событий, заказов и агентского matchmaking. Репозиторий одновременно поддерживает разные host runtimes, поэтому нельзя предполагать одинаковые оболочки или prompts.

## 4. Пайплайн и архитектура

AgentVillage — слой skills/workspace/config вокруг agent runtime, а не самостоятельная LLM. Пользователь настраивает локальную оболочку либо получает hosted runtime; установка настраивает доступ к API, расписание фоновых задач и информацию об участнике. Скрипт собирает для утреннего дайджеста ограниченный набор данных, после чего модель пишет персонализированное сообщение. Для memory signal sync локальный preflight проверяет наличие новых данных и лишь при значимом событии будит модель. Участник может иметь собственные цели и согласие, которые проходят approval-процесс; часть операций требует точного подтверждения. Общий Index/EdgeOS backend хранит действия поиска и согласования контактов.

README не даёт размера выборки, продольного протокола, контрольной группы или валидированных социальных outcome. Встроенные журналы и данные проекта пригодны как источник для будущего исследования, но их наличие не означает публикацию результата. Чтобы делать выводы, нужны согласие участников, описание отбора, метрики взаимности и принятия предложений, длительность участия и аудит различий backend/model.

## 6. Основные результаты

Проверяемый результат — работающий инфраструктурный проект с процедурами onboarding, расписания, памяти, согласований и подключения к общим сервисам. README не сообщает частоты дружбы, числа контактов, эффекта рекомендаций или сравнения с участниками без агентов. Любые цифры из сторонних блогов/медийных описаний нельзя приписывать README без проверки.

## 7. Интерпретация

Это полевая платформа для персональных агентов, встроенных в реальное временное сообщество. Именно реальные участники и общий календарь создают социальный контекст, а агенты помогают с поиском/координацией. Это отличается от полностью автономного LLM-социума из 20 агентов; люди, организаторы и инфраструктура остаются существенными причинами наблюдаемого взаимодействия.

## 8. Ограничения и воспроизводимость

В репозитории упоминаются частные backend-ы и данные; часть кода/операторской конфигурации непублична, поэтому публичный README не обеспечивает воспроизведение всего поля. Функциональность и расписания меняются по версиям. Модель, лимиты токенов и fallback могут быть заданы администратором; сравнение поведения без фиксации этих факторов некорректно. Полевые данные требуют этического согласия и защиты личной информации.

## 9. Значение для Лаборатории № 57 и «Верхума»

Проект наводит на дизайн сравнения: каждому человеку — личный агент и память, но контакты проходят через общий механизм discovery и согласия. Можно тестировать, как меняются связи при рекомендациях центра, при свободном выборе и при прозрачном публичном расписании. С точки зрения активных систем важно измерять, как инфраструктура меняет множество допустимых действий, а не приписывать самоорганизацию только агентам.
