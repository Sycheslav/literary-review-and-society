# Concordia: библиотека генеративных агентных симуляций

**Оригинальное название:** Concordia: A library for generative social simulation. **Авторы:** Alexander Sasha Vezhnevets, John P. Agapiou, Avia Aharon, Ron Ziv, Jayd Matyas, Edgar A. Duéñez-Guzmán, William A. Cunningham, Simon Osindero, Danny Karmon, Joel Z. Leibo. **Год:** 2023; текущий репозиторий прочитан 29.10.2026. **Тип:** открытая библиотека; отдельно существует технический отчёт arXiv:2312.03664. [Репозиторий](https://github.com/google-deepmind/concordia), [техотчёт](https://arxiv.org/abs/2312.03664). Ниже — описание программного инструмента по README, не изложение техотчёта.

## 1. Главный вопрос и ответ

Concordia отвечает на инженерный вопрос: как конструировать симуляции, в которых генеративные агенты действуют в физическом, социальном или цифровом мире и получают последствия действий в общей среде. Центральный паттерн напоминает настольную ролевую игру: агенты формулируют действие обычным языком, а специальная сущность Game Master (GM) моделирует мир, оценивает допустимость действия и формирует результат/наблюдение. Это гибкая библиотека, а не готовый доказанный симулятор общества и не эмпирический вывод, что агенты естественно создают институты.

## 2. Требования и заявленные возможности

Проект ориентирован на исследовательские задачи в социальных науках, безопасности, этике, когнитивной нейронауке и экономике. README не задаёт общую гипотезу. Его основное проектное обещание — модульность компонентов, среды и движка позволяет собирать разные симуляции, менять инструкции, память и механику хода, сохраняя общий интерфейс.

## 3. Агенты, среда и состояние

Симуляция собирается из entities; сущность содержит компоненты, отвечающие, например, за инструкции, память и выбор действия. Prefab — готовый шаблон сущности, который можно параметризовать именем, инструкциями и целью. Важно, что роли player и GM назначаются на вызове цикла, а не являются неизменными типами агента. Среда может быть физической, социальной или цифровой. Для ассоциативной памяти нужен embedder фиксированной размерности; языковые модели подключаются через API.

README приводит учебный пример четырёх друзей, застрявших в заснеженном пабе, с конфликтом вокруг аварии автомобиля. Вопросы агентской схемы отсылают к March и Olsen: «что за ситуация», «кто я» и «что такой человек делает в такой ситуации». Это хороший пример того, как модель агентности уже направляет поведение через заданные идентичности и нормы; его нельзя выдавать за возникшую без предпосылок дружбу.

## 4. Архитектура и пайплайн

Разработчик выбирает prefab и его параметры, компонует entity из инструкций/памяти/сенсорных модулей/действия, затем задаёт среду и цикл исполнения. `run_loop` распределяет роли игрокам и GM. Игровые агенты выдают предполагаемые действия, GM предоставляет наблюдения и разрешает последствия, после чего обновляется контекст для следующего хода. Архитектура допускает поочерёдные, одновременные и асинхронные действия; точное расписание определяется интерфейсом окружения. Инструменты работы с prompt и context вынесены отдельно. Пользователь может подключать любую генеративную LLM API и ассоциативный embedder; результат зависит от выбранных моделей.

## 5. Дизайн и измерения

README не задаёт стандартного числа агентов, метрик или baseline: это библиотека-конструктор. Автор эксперимента должен указать модель мира, протокол действий, память, prompts, число прогонов и outcome. Без фиксации версий prefab, конфигураций компонентов и GM невозможно отделить эффект LLM от эффекта сценария и правила разрешения действий.

## 6. Результаты

Как software artifact Concordia предоставляет повторно используемые сущности, компоненты, prefab, environment interfaces и примеры; проверяемый технический результат — наличие модульного кода и инструкций установки (PyPI `gdm-concordia`, подключение собственной LLM API). README не сообщает контролируемых сравнительных результатов или метрик точности симуляции. Работу следует цитировать как программную платформу, а эмпирические результаты искать в конкретных опубликованных симуляциях.

## 7. Что следует и чего не следует

Платформа делает явной важную прослойку между текстовым намерением агента и действием в мире: GM превращает реплику в проверяемое последствие. Это удобно для аудита и механизма управления. Но GM также становится центральным источником смещения: его интерпретация может задавать исход. Поэтому нельзя приписывать поведение «самому социуму», если разрешение действий и наблюдения контролирует центральная сущность.

## 8. Ограничения и воспроизводимость

Нужен внешний LLM API и embedder; модель, провайдер, контекст, компоненты и GM следует фиксировать. README предупреждает, что качество зависит от модели и что часть зависимостей может требовать настройки среды. Текущий README ссылается на более новый design-pattern paper, но это изложение касается только библиотеки и не проверяет его утверждения.

## 9. Значение для Лаборатории № 57 и «Верхума»

Concordia может послужить быстрым каркасом для прототипа лабораторной среды с раздельными журналами агента и среды: agent сообщает предложение, GM проверяет ограничения механизма, журнал фиксирует принятое действие. Для сопоставления с ТАС можно варьировать, кто выполняет роль центра/GM, что он знает и кто наблюдает решения. Для вопроса о «Верхуме» этот слой нужен для различения реальной кооперации и исхода, который фактически произвёл симулятор.
