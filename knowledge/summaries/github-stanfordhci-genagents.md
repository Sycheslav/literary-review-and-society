# genagents: генеративные агенты, отвечающие от имени реальных людей

**Проект:** StanfordHCI/genagents. **Авторы:** репозиторий Stanford HCI; кодовая база проекта. **Статус:** открытый исследовательский проект, не экспериментальная статья. **Источник:** [README репозитория](https://github.com/StanfordHCI/genagents) и пример кода; прочитанный README сохранён локально как [fulltext](https://github.com/StanfordHCI/genagents), снимок на дату подготовки.

## 1. Главный вопрос и ответ

Проект предоставляет инструменты для построения генеративных агентов, имитирующих ответы отдельных людей по интервью или демографической информации. Главный вклад — инфраструктура, связывающая личную информацию, память агента и опросные/экспериментальные запросы. Это инструмент моделирования поведения респондентов; он сам по себе не демонстрирует, что агенты формируют общество.

## 2. Что проверяли: вопросы и гипотезы

README не формулирует научные гипотезы: это репозиторий и программные артефакты. Его заявленная цель — дать исследователям возможность строить и взаимодействовать с агентами по собственным данным и использовать демонстрационный банк. Предположение, что такие агенты воспроизводят поведение людей, требует валидации в сопровождающей статье и не должно выводиться только из факта наличия кода.

## 3. Агенты, среда и исходные условия

Архитектура включает класс `GenerativeAgent`, scratchpad с личной информацией, журнал воспоминаний, возможность рефлексии, сохранение/загрузку состояния и вопросы с вариантами ответа. README описывает банк более чем 3000 демонстрационных агентов, построенных от демографических данных General Social Survey; имена и адреса синтетические. Отдельно заявлен будущий или ограниченно доступный банк более 1000 агентов, основанных на интервью, включая около 2000 часов интервью, доступ к индивидуальным ответам зависит от проверки исследовательского запроса.

## 4. Метод и пошаговый пайплайн

Исследователь инициализирует агента, помещает в scratchpad его профиль, добавляет события в память с временными метками, при необходимости вызывает `reflect`, после чего задаёт вопрос или стимул и получает сгенерированный ответ. Состояние можно сохранять в папку агента и восстанавливать для последующих эпизодов. В структуре репозитория есть движок симуляции, банк агентов и общие функции для запросов GPT, JSON-ответов и обработки промптов. Это интерфейс для экспериментов, а не готовый многоагентный симулятор с заданными правилами коммуникации.

## 5. Экспериментальный дизайн и метрики

README не описывает единый эксперимент, контрольные условия, число прогонов или метрики. Инструмент позволяет задавать categorical-response вопросы и свободные стимулы; проектная статья/данные должны определять качество репликации, межагентную вариативность и стабильность ответов. Демографический банк и агенты интервью имеют разный источник индивидуальных характеристик, поэтому их нельзя считать взаимозаменяемыми.

## 6. Основные результаты

У репозитория нет собственного результата эксперимента, который можно численно пересказать. Наблюдаемая функциональность — создание, сохранение и запрос агента; README сообщает о планах/условиях доступа к интервью-основанному банку. Наличие 3000 профилей означает масштаб банка данных, а не 3000 независимо проверенных цифровых двойников.

## 7. Что из этого следует и чего не следует

Архитектура полезна, если Лаборатория 57 хочет включить контролируемые индивидуальные различия в симуляцию: у каждого участника есть отдельная память и профиль. Но применительно к социуму надо отдельно реализовать сеть, общую среду, доступ к сообщениям, экономические стимулы и механизм изменения правил. Ответы агента не равны ответам человека и не подтверждают психологическую идентичность.

## 8. Ограничения и воспроизводимость

Пример конфигурации опирается на OpenAI API и упоминает GPT-4/GPT-3.5; зависимости и ключи задаются локально. Полный банк реальных интервью не открыт из-за приватности; доступ для индивидуальных ответов предполагает рассмотрение запроса, а агрегированные ответы описаны как отдельный план доступа. Версия `main` может изменяться. Для воспроизводимости фиксировать git commit, параметры API, исходные источники персон, версии интервью/опроса, промпты и правила памяти. Демографически синтетический банк требует собственной валидности для каждой исследовательской задачи.

## 9. Значение для Лаборатории № 57 и «Верхума»

Переносимый элемент — раздельные личные состояния и возможность исследовать, как исходная неоднородность отражается на коллективном решении. Можно начать с синтетических профилей, задав приватные предпочтения и ограниченную видимость памяти; сравнить однородный и разнообразный состав, а затем ротировать участников. Это позволит проверить перенос нормы/института без хранения личных интервью. Связь с активными системами — разная информированность и цели агентов, тогда как общие институты должны быть введены отдельным механизмом.
