# Mesa-LLM: языковые модели в агентном моделировании Mesa

**Проект:** `mesa/mesa-llm`. **Авторы:** сообщество Mesa. **Статус:** открытая библиотека, README предупреждает об активной разработке и возможных изменениях API. **Источники:** [репозиторий](https://github.com/mesa/mesa-llm), [документация v0.3.2](https://mesa-llm.readthedocs.io/en/stable/overview.html), локально сохранённый README.

## 1. Главный вопрос и ответ

Mesa-LLM связывает LLM-рассуждение с обычной симуляцией Mesa: среда, агентная активация, время, сбор данных и визуализация остаются у ABM-фреймворка, а языковая модель подменяет или дополняет принятие решений. Это практический конструктор для исследовательских моделей, а не эмпирическое доказательство эмерджентного поведения.

## 2. Что проверяли: вопросы и гипотезы

Как встроить языковое рассуждение в стандартный жизненный цикл агента Mesa, не отказываясь от расписания и контролируемого мира? Проект не предъявляет гипотезу о конкретном социальном эффекте. Вопрос о том, какие нормы/роли появятся, зависит от среды и промптов пользователя.

## 3. Агенты, среда и исходные условия

Основная абстракция — `LLMAgent`, совместимый с Model/Agent Mesa. Разработчик определяет наблюдение, промпт, reasoning module и возможную память/инструменты. В документации перечислены OpenAI, Ollama и другие бэкенды; README также явно упоминает OpenRouter, Anthropic, xAI, Hugging Face, Novita и Gemini. Среда и действия не предписаны: они строятся средствами Mesa.

## 4. Метод и пошаговый пайплайн

При `model.step()` Mesa активирует агентов по обычной схеме. Агент строит языковой prompt из состояния/наблюдения; reasoning-компонент запрашивает модель (например, ReAct); затем код модели применяет план как действие. Память опциональна: документация приводит STLTMemory и EpisodicMemory; инструменты могут превращать вывод в исполняемые действия. Есть асинхронный `astep` для параллельного вызова и пример отправки сообщений соседям. Учебный tutorial отдельно предупреждает, что в начальном примере action execution отложено.

## 5. Экспериментальный дизайн и метрики

Библиотека не задаёт бенчмарк, baseline, число сидов или метрики. Их обеспечивает конкретный ABM: Mesa даёт расписание (последовательное, перемешанное, staged и т. д.), `DataCollector`, пространство и визуализацию. Для экспериментов важно отделять влияние LLM от порядка активации, промпта, memory module, API-провайдера и ограничений на сообщения.

## 6. Основные результаты

Как проект программная библиотека сообщает возможности и примеры, но не экспериментальные результаты о поведении сообщества. Техническая ценность — интеграция естественно-языкового рассуждения с воспроизводимым циклом ABM, возможность разных backend и настройка памяти/коммуникации. README предупреждает об активной разработке; документация v0.3.2 даёт более стабильную версионную точку.

## 7. Что из этого следует и чего не следует

Mesa-LLM может быть прототипной основой стенда на 20 агентов, особенно если исследователям нужны явные правила мира и запись состояний. Наличие функции `send_message` не означает, что агенты самостоятельно создадут устойчивые связи; действие и список адресатов задаёт разработчик. Отдельные API-вызовы могут давать задержки и стоимость, поэтому локальная среда должна быть детерминирована и логировать все события.

## 8. Ограничения и воспроизводимость

API проекта может меняться; README на момент чтения говорит, что проект развивается. Различаются текущие возможности репозитория и версии документации, поэтому фиксировать версию пакета и Git commit. Повторяемость LLM-вызовов ограничена стохастикой и изменениями провайдера. Следует сохранять модельный ID, промпты, температуру, историю наблюдений, действия, ошибки JSON, токены и фактический endpoint. Одновременная активация может создавать race conditions, а не моделировать человеческое коллективное решение.

## 9. Значение для Лаборатории № 57 и «Верхума»

В Mesa удобно сделать факторные ABM-опыты «граф связи × порядок ходов × память × стимулы», сохраняя один и тот же мир между условиями. Можно операционализировать четыре культуры верхума через различные правила доступа к информации и распределения результата. Проверка должна сравнивать LLM-агентов с правилами/случайным baseline, а не заключать о социальности по красивому текстовому логу.
