# Agent Scaling: код и артефакты к статье о границах сотрудничества

**Проект:** `ybkim95/agent-scaling`. **Связанный оригинал:** *Capable language models can outgrow the benefits of collaboration* (Nature Machine Intelligence, 2026). **Тип:** репозиторий воспроизводимости, не самостоятельная статья. **Источник:** [GitHub](https://github.com/ybkim95/agent-scaling/); локально сохранённый README.

## 1. Главный вопрос и ответ

Репозиторий предоставляет конфигурации, трассы, наборы данных и скрипты для исследования масштабирования агентных систем. Он нужен, чтобы проверять статью о том, при каких возможностях базовой модели мультиагентное сотрудничество перестаёт приносить пользу. В отличие от статьи, репозиторий сам не является систематическим сравнением и не даёт независимой оценки выводов.

## 2. Что проверяли: вопросы и гипотезы

Вопрос связанной статьи — меняется ли выигрыш от сотрудничества при росте компетентности одиночной модели, сложности задачи и стоимости коммуникации. В README репозитория нет новых гипотез: это открытые артефакты. Поэтому проверяемый результат следует брать из статьи, а не реконструировать из названия или списка папок.

## 3. Агенты, среда и исходные условия

В репозитории видны каталоги `agent_scaling`, `datasets`, `data`, `example_traces`, `prompts`, `run_conf`, `scripts`, `tests` и `colab_analysis`. По README это набор материалов к статье, включающий промпты, конфигурации запуска и трассы. Точные модели, задания и условия фиксируются в соответствующих конфигурациях/статье; README не даёт достаточных оснований перечислять их как экспериментальные факты.

## 4. Метод и пошаговый пайплайн

Пользователь клонирует проект, настраивает окружение/ключи по README, выбирает конфигурацию запуска, доступные данные/пrompt и запускает скрипты. Трассы показывают примеры взаимодействия; tests предназначены для проверки кода, а Colab-анализ — для обработки результатов. При повторении следует сравнивать выходы как для одиночного агента, так и для многоагентного режима согласно первичной статье, соблюдая фиксированные параметры задачи и расхода.

## 5. Экспериментальный дизайн и метрики

Поскольку это артефактный репозиторий, сам README не определяет дизайн. Он даёт ориентиры на run configs, промпты и scripts; метрики статьи и их единицы надо сверять с разделом Methods/Supplementary Information научной публикации. Репозиторий содержит тесты для программной корректности, но успешный тест не подтверждает эмпирический вывод.

## 6. Основные результаты

У репозитория нет самостоятельных поведенческих результатов. Его значимый вклад — возможность изучить, воспроизводить и модифицировать конфигурации и примеры трасс связанной работы. Фраза о «способных моделях, перерастающих выгоды сотрудничества» принадлежит названию статьи, а количественные эффекты нельзя приписывать README.

## 7. Что из этого следует и чего не следует

Для Лаборатории 57 важно использовать repo как шаблон для контролируемых сравнений индивидуального и коллективного решения, с явной фиксацией бюджета вычисления. Это потенциально помогает не трактовать «больше агентов» как автоматически лучше. Но статья касается инструментального сотрудничества в задачах, а не возникновения институтов, социальной памяти или дружеских связей.

## 8. Ограничения и воспроизводимость

GitHub-ветка `main` изменяема, поэтому нужно указывать SHA commit и конкретные версии окружения. Некоторые данные или API могут требовать отдельного доступа. Провайдеры и модели со временем меняются, так что необходимы журнал параметров, хеши промптов и сохранённые трассы. Для научной цитаты требуется сопровождать репозиторий публикацией и уточнять, какие результаты реплицированы самим кодом.

## 9. Значение для Лаборатории № 57 и «Верхума»

Можно перенести структуру репозитория для будущего стенда: versioned prompts, run configs, примеры разговоров, datasets и автоматизированный анализ. Лабораторное продолжение — добавить «социальный» режим с частными интересами, ограниченными каналами и изменяемым графом, чтобы узнать, когда сотрудничество окупается в группах с конфликтом целей. Это уже новый опыт, а не вывод исходной статьи.
