=== id: github-raadbintareaf-silica-benchmark
title_en: SILICA Benchmark (official code for human behavioral-distribution evaluation)
title_ru: SILICA Benchmark (официальный код для оценки распределений человеческого поведения)
## summary
SILICA — кодовый бенчмарк групп LLM на интерактивных социальных играх с человеческими якорями, тестами на возмущения (perturbation) и тестами на загрязнение данных.
## design
README перечисляет пять сред: повторяемая дилемма заключённого (repeated Prisoner's Dilemma); игра с общественными благами (Public Goods Game) с наказанием и без него; торг по схемам «ультиматум», «диктатор» и «доверие» (Ultimatum/Dictator/Trust bargaining); запросы денег на 11–20 (11–20 money request); игра в называние (naming game) с чаевыми (tipping); плюс проверки узнавания (recognition probes). Варианты C0–C3 меняют формулировку, представление или структуру задачи, включая no-dilemma, rejection pays, inverted ladder, glyphs и anti-coordination. Есть человеческие якоря (human anchors) D1–D7 с пометками о происхождении данных (provenance flags) и классические базовые модели: Roth–Erev, условные кооператоры (conditional cooperators), TitForTat и минимальная модель naming game. Бенчмарк одновременно оценивает соответствие распределению людей (fidelity), устойчивость к переформулировкам (робастность) и устойчивость к загрязнению данных (contamination resistance); конкретная статья определяет метрики и человеческую основу.
## tech
Официальный репозиторий содержит конфигурации экспериментов в формате YAML, промпты и рендереры как библиотеку для аудита (audit library), варианты C0–C3 с формальными проверками, среды, модельные бэкенды openai-compatible, vLLM, Ollama и API, режим mock и аналитику W1/TV/kappa/swing/sign-stability. README содержит тест работоспособности на CPU без API (менее 2 минут), команды для локального vLLM с моделью Qwen/Qwen3-14B и один реальный базовый запуск pd baseline. Все реальные результаты должны получаться на бэкенде пользователя или сервера; демонстрационные результаты mock в статью не входят.
## prompts
Возмущения промптов (prompt perturbations) задаются через PerturbationSpec и рендереры; проверки узнавания (recognition probes) дополняют проверки на загрязнение данных (contamination checks). Есть отдельный промпт и обработка для правила, меняющего поверхность игрового сюжета. Соответствие человеческому якорю должно пересчитываться по исходным датасетам: README помечает часть источников как TO_VERIFY/UNCONFIRMED.
## costs
README не приводит итоговой стоимости API для статьи; запуск на локальном vLLM использует GPU, а smoke-тест в режиме mock выполняется без API. Число запусков не равно реальным денежным расходам.
## results
Это кодовый репозиторий; он не сообщает ключевого эмпирического результата как самостоятельного источника. Явная граница достоверности (integrity boundary): результаты mock имеют демонстрационный масштаб, а каждое число для статьи должно быть получено на сервере с реальными бэкендами моделей и обработано скриптами фазы 6 (Phase 6 scripts). Человеческие якоря с пометками требуют перепроверки по первичным данным до подачи статьи.
## conclusions
Репозиторий способствует строгому сравнению распределений популяций LLM с распределениями людей и разработке формальных проверок возмущений и загрязнения данных (perturbation/contamination probes), но README прямо ограничивает демонстрационные результаты и требует подтверждения происхождения якорей (provenance).
## limits
README может описывать активную разработку и незавершённую фазу 6; машины пользователей и провайдеры дают различия в конечных точках (endpoint). Mock не считается доказательством для статьи. Сама точность соответствия человеческому распределению не гарантирует, что выявлены причинные социальные механизмы.

=== id: github-ruc-gsai-yulan-onesim
title_en: YuLan-OneSim (социальный симулятор на основе LLM)
title_ru: YuLan-OneSim (социальный симулятор на основе LLM)
## summary
YuLan-OneSim — платформа с сценариями социальной симуляции, API-конфигурацией и распределённой архитектурой; заявлены 50+ сценариев и масштаб до 100 000 агентов.
## design
README описывает платформу для социальных наук и ИИ (social science and AI), где сценарии создаются в диалоге на естественном языке и запускают агентные модели; библиотека содержит более 50 стандартных сценариев в восьми областях. Система заявляет эволюционируемую симуляцию (evolvable simulation), в которой модель автоматически улучшается по внешней обратной связи, крупномасштабную симуляцию с распределённым исполнением и «ИИ-исследователя социальных наук» (AI social researcher), который может пройти путь от постановки темы до отчёта. Это перечень функций по документации, а не протокол одного эксперимента с человеческой контрольной группой.
## tech
Репозиторий содержит конфигурацию Docker, веб-интерфейс на localhost:8000, настройки ключей и конечных точек (endpoint) в `config/config.json` и `config/model_config.json`, документацию и образ Docker Hub. Требуется Python 3.10+ (или Docker). README предлагает несколько API-провайдеров через конфигурацию; статья опубликована на arXiv как 2505.07581, релиз — 2025-05-13. Конкретные модели и механизмы сценария следует сверять по статье и документации.
## prompts
Сценарии задаются на естественном языке; пользователь настраивает модель и ключи, платформа превращает сценарий в симуляцию. README не раскрывает единого шаблона промпта для всех сценариев и полных промптов времени выполнения (runtime prompts); каждый сценарий может задавать другие инструкции.
## costs
Расходы на API не указаны. Облачные и локальные вычислительные расходы для масштаба 100 000 агентов в README также не конкретизированы; заявленная возможность не равна опубликованной смете.
## results
README утверждает поддержку до 100 000 агентов и каталог из 50+ сценариев; это самоописание проекта, а не количественная демонстрация точности или скорости. Эмпирические результаты следует искать в статье arXiv:2505.07581 и в отдельных результатах бенчмарков.
## conclusions
YuLan-OneSim — инфраструктурный проект, который объединяет интерфейс сценариев, многомодельную интеграцию и масштабируемый запуск. Платформенные обещания требуют отдельной проверки по релевантным режимам и публичным результатам.
## limits
README содержит рекламные формулировки («groundbreaking»), которые на самой странице не подкреплены тестами и данными о стоимости. Масштаб до 100 тыс. агентов не означает 100 тыс. одновременных вызовов или работу на одной машине. Параметры сценариев и степень участия человеческой обратной связи (human feedback) различаются.

- README: агенты строятся по качественным интервью о жизни людей и воспроизводят ответы этих людей на социально-научные измерения; заявлено около 2000 часов интервью и 1000 агентов (полный банк не публикуется).

## design
По README исследование основано на качественных интервью: участники рассказывали о своей жизни по протоколу интервью, а агент строит модель личности на этом материале. Затем агенту задают вопросы социально-научных опросов (категориальные варианты, числовые шкалы, открытые вопросы) и сравнивают его ответы с ответами реального участника. В самом README не приведены ни протокол интервью, ни число вопросов, ни метрики точности, ни схема выборки, ни процедура сравнения: эти сведения отсылаются к статье Park et al. (2024). Открытая часть проекта включает два компонента: инструменты для создания и опроса агентов по собственным данным и банк более 3000 демографических агентов, построенных на GSS. Ещё один пример — агент одного из авторов, созданный по тому же протоколу интервью. Полный банк на 1000+ агентов публично не опубликован. Социальная среда, множество агентов, которые общаются друг с другом, и временная динамика симуляции в README не описаны.
## tech
Требования по README: Python 3.7 и выше; API-ключ OpenAI с доступом к GPT-4 или GPT-3.5-turbo. В примере конфигурации (settings.py) задано LLM_VERS = "gpt-4o-mini", то есть по умолчанию в коде используется другая модель, чем указано в требованиях; это расхождение стоит отметить. Параметр MAX_CHUNK_SIZE = 4 задаёт размер порции при обработке. Структура репозитория: модуль genagents (класс GenerativeAgent, interaction.py, memory_stream.py), каталог simulation_engine (settings, global_methods, gpt_structure, llm_json_parser и каталог prompt_template со всеми LLM-промптами), каталог agent_bank с популяциями gss_agents и single_agent. Память: поток наблюдений (remember с временным шагом time_step) и рефлексия по якорю (reflect(anchor=..., time_step=...)); агент сохраняется и загружается из папки (save / agent_folder). Версии библиотек фиксируются в requirements.txt, содержимое которого в тексте README не раскрыто. Расписание, параллелизм и инфраструктура для многоагентных экспериментов в README не описаны.
## prompts
Все LLM-промпты, как указано в README, находятся в каталоге simulation_engine/prompt_template/. Их точные тексты в проверенном тексте README не приведены; для анализа нужно открыть репозиторий. Пример вызова: agent.categorical_resp с вариантами ответа, agent.numerical_resp с диапазоном [1, 10], agent.utterance с диалогом интервьюера. Разграничение между промптами, которые задают личность, и промптами, которые задают ответ на вопрос, в README не описано.
## costs
README не содержит опубликованных расходов, числа токенов или тарифов. Упоминается требование API-ключа OpenAI, но сумма затрат на 1000 агентов или на опрос не указана: не опубликована.
## results
В README нет количественных результатов: точности воспроизведения ответов, корреляций, сравнения с контрольными группами или ошибок не приводятся. Отсылка к статье Park et al. ## conclusions
Авторы README заявляют, что агенты, построенные по интервью, воспроизводят ответы участников на социальные измерения и могут служить основой для инструментов изучения индивидуального и коллективного поведения. Это заявление о назначении проекта, а не проверенный вывод. Интерпретация «коллективного поведения» здесь относится к агрегированию индивидуальных ответов, а не к взаимодействию агентов.

Агенты отвечают на опросы, а не действуют в среде; для вопросов о связях, ролях и нормах социума этот подход не даёт прямых данных. ## design
Каждая партия Resistance: Avalon состоит из до пяти миссий; добрые побеждают после трёх успехов, злые — после трёх провалов или убийства Merlin. В миссии есть обсуждение, предложение команды, голосование и скрытый выбор участников миссии (успех или провал). Главный турнир: пять агентов играют 50 игр подряд с памятью между ними. Дополнительно есть турниры на 5–10 игроков с полной памятью и одиночные игры без памяти. Репозиторий заявляет 188 полных логов игр с репликами, голосами и рассуждениями (reasoning). Условия сравнивают уровни усилий рассуждения (reasoning effort) low, medium и high и несколько количеств игроков; сам README описывает данные, а не опубликованный контролируемый дизайн статьи (article).
## tech
Заявленная модель — GPT-5.1; уровни усилий рассуждения (reasoning efforts) настраиваются. После каждой игры агенты создают самоанализ (self-reflection) и заметки о других игроках, затем используют их в следующих играх. ## prompts
Агенты получают скрытые роли и игровое состояние (game state); память содержит роли, предполагаемую ложь и доверие, сформированные в предыдущих партиях. Полные системные промпты в извлечённой части README не приведены. Структура игры заранее задаёт обсуждение, выбор и голосование, а также цели ролей (role objectives).
## costs
README не приводит счёта за API и числа токенов. GPT-5.1 и уровень усилий рассуждения влияют на расходы, но стоимость в доступной документации не оценивалась.
## results
По README: репутации начали проявляться примерно к игре 20; Charlie назван «subtle» (тонким) 38 раз. Игроков с высокой репутацией выбирали в команды на 45% чаще. Точность убийства или идентификации Merlin — 67% при low, 75% при medium, 100% при high; 90% неправильных убийств пришлось на обычных добрых игроков, которые логически выводили роль. Эти цифры принадлежат README проекта; знаменатель, состав логов и статистическую неопределённость нужно проверить по набору данных и статье.
## conclusions
Автор утверждает, что память между играми поддерживает репутацию, доверие и стратегическую адаптацию, но ошибочная дедукция способна спутать логический вывод с секретным знанием. Протокол позволяет наблюдать повторяющиеся социальные сигналы.
## limits
188 игр включают разные режимы и размеры, а ключевые выводы относятся к конкретной серии из 5 агентов и 50 игр. Набор создан одним проектом и, возможно, не имеет независимой репликации; «возникло естественно» — интерпретация авторов, поскольку память и рефлексия заданы архитектурой.
