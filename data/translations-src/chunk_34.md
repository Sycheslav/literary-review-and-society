=== id: github-aismithlab-humanstudy-bench
title_en: HumanStudy-Bench (код и бенчмарк повторного исполнения human-subject исследований)
title_ru: HumanStudy-Bench: код и бенчмарк повторного исполнения исследований с участием людей
## summary
HumanStudy-Bench — открытый стенд для воспроизведения 12 человеческих исследований (более 6 000 испытаний) и оценки того, совпадают ли выводы LLM-агентов с человеческими.
## design
README называет стандартизированный стенд (testbed): исполнительный движок (execution engine) восстанавливает полные протоколы опубликованных исследований с участием людей (human-subject), затем проигрывает испытания (trials) и запускает исходный статистический анализ в общей среде. Начальный набор содержит 12 исследований по когнитивным задачам, стратегическому взаимодействию и социальной психологии, совокупно более 6 000 испытаний; исходные человеческие выборки варьируются от десятков до более 2 100 участников. Бенчмарк специально стремится оценивать совпадение на уровне научного вывода, а не только совпадение отдельных ответов.
## tech
В README присутствуют PAS (Probability Alignment Score), оценивающий вероятность, что популяция агентов и людей согласуется с одной гипотезой с учетом статистической неопределенности человеческого базового варианта (baseline), и ECS (Effect Consistency Score), сравнивающий величину и паттерн поведенческого эффекта. Репозиторий предлагает скрипт запуска отдельного исследования или всей батареи, сбор результатов, токенов и стоимости; можно добавлять новые исследования через конвейер (pipeline). Заявлена лицензия MIT. README показывает пример Mistral Nemo и предустановку демографического профиля (demographic profile preset), но это лишь пример вызова, не универсальная модель.
## prompts
Дизайн агентов задаётся через предустановки (presets) и пользовательские методы (custom methods), которые генерируют промпт по профилю; в README приведён пример инструкции «представь профиль» для респондента. Протоколы исследований реконструируются из опубликованных работ. Это программно изменяемая часть бенчмарка, поэтому сравнение моделей требует фиксировать профиль, персону и предустановку.
## costs
README указывает, что результаты могут включать токены и стоимость, но не задаёт единого бюджета для всей библиотеки; денежная стоимость зависит от модели, провайдера и исполнения каждого исследования. Пример HumanStudy-Bench не является фиксированным тарифом API.
## results
Как программный артефакт README сообщает о 12 включённых исследованиях и более 6 000 исходных испытаний; эти масштабы характеризуют набор, а не успешность имитации LLM. Численные результаты PAS/ECS конкретной версии бенчмарка нужно брать из связанной статьи или таблицы лидеров (leaderboard) и привязывать к модели и дизайну агента.
## conclusions
Репозиторий помогает развести компетентность базовой модели и решения дизайнера агента, повторно исполняя человеческие протоколы и сравнивая научные выводы. Воспроизводимость обеспечивается через открытые сценарии и скрипты, но не гарантируется одной лишь публикацией кода.
## limits
README отражает версию ветки статьи (paper); новые исследования требуют реконструкции, а сходство с человеческими выводами в 12 сценариях не обобщается на все социальные науки. Настройки профиля, промпты, модели и оценивания — существенные факторы. Для реальных вызовов требуются API-ключи.

title_en: YClient-Reddit (YSocial client fork for Reddit-style simulations)
title_ru: YClient-Reddit: форк клиента YSocial для симуляций в стиле Reddit
## summary
Форк YSocial для Reddit-подобных сценариев с постами, ветками комментариев, голосованием, лентой и конфигурациями сообщества r/technology.
## design
Репозиторий меняет исходный клиент YSocial — клиент-серверную симуляцию цифрового двойника онлайн-платформы — чтобы лучше моделировать Reddit-подобные сообщества. README перечисляет адаптацию промпта (prompt) и логики взаимодействий для публикации, комментариев и голосований, изменение структур данных и параметров для сообществ с ветками обсуждений (thread-based), модификации рекомендательной системы (recommender) и ленты (feed) и скрипты/параметры Reddit-экспериментов. Включены две конфигурации r/technology: небольшая модель сабреддита (subreddit-модель) и более крупное постоянно растущее сообщество с глубокой структурой дискуссий. Это кодовый форк, не отдельная эмпирическая статья; README не предоставляет измеренные социальные результаты.
## tech
Исходный YSocial клиент/документация остаются источником общих setup, функций и технических деталей. Данный форк выделяет модификации, дополнительные experiments/tech и experiments/tech-v1 конфиги, промпты и RSS-ленты (RSS-feeds). Не переносить возможности/метрики базового YSocial на форк без проверки кода. Конкретные модели и размеры группы в доступном README не сообщены.
## prompts
README прямо сообщает, что промпты и логика взаимодействий адаптированы под публикации, комментарии и голосования в стиле Reddit (posting/commenting/voting); промпты и RSS-ленты хранятся в сценариях. Это экспериментаторские настройки симуляции, не естественные нормы реальных форумов.
## costs
Репозиторий не указывает API-тарифов, суммарных токенов или стоимость запуска.
## results
Источник описывает наличие конфигураций, ленты и социальной механики, но не приводит результаты сравнительного исследования. Создание «растущего успешного subreddit» — название/цель сценария, не доказанный исход модели.
## conclusions
Форк может служить программной основой для сравнения поведения в thread-структурах и на Reddit-подобной платформе, но эмпирические утверждения (claims) нужно брать из отдельной публикации или логов.
## limits
README краткий, отсылает к базовой документации; отсутствуют sample size, модели, метрики и контрольные условия. Поведение задаётся промптами и механикой ленты и рекомендаций.

=== id: github-camel-ai-oasis
title_en: OASIS: Open Agent Social Interaction Simulations with One Million Agents
title_ru: OASIS: открытая платформа симуляции социальных взаимодействий миллиона агентов
## summary
OASIS — симулятор социальных платформ в стиле Twitter и Reddit с LLM-агентами, нативными действиями платформы, рекомендательными системами, часами и журналированием состояния.
## design
Пользователь задаёт профили агентов и граф, выбирает тип платформы, набор действий и систему рекомендаций, затем двигает симулируемое время шагами среды. Агенты могут публиковать, ставить отметки, подписываться, комментировать, репостить и выполнять другие действия; платформа показывает реакции и контент. Два стандартных типа платформы воспроизводят возможности Twitter и Reddit; также поддерживаются пользовательские конфигурации. SQLite хранит действия и связи, масштабирование времени Clock задаёт ход симуляции. Допускаются различные модели, инструменты и промпты для агентов; фиксированного экспериментального протокола нет. В каждой работе нужно задавать размер популяции, стартовые профили, расписание шагов, ленту, действия и модель.
## tech
README CAMEL-AI/oasis заявляет масштаб до 1 млн пользователей и 23 действия. Конфигурация документации включает agent_graph, platform, database_path, semaphore (по умолчанию 128), профили пользователей, набор действий и необязательные embedding/recommendation. SocialAgent наследует CAMEL ChatAgent и содержит сведения о пользователе/память. Есть случайные рекомендации, рекомендации Reddit по вовлечённости, персонализация Twitter и опциональные графовые эмбеддинги TWHin. Поля профиля user_char/description становятся исходным текстом идентичности в системном промпте (system prompt). Платформа предоставляет примитивы (профиль, граф действий, постоянные журналы), но автоматически не гарантирует социальное поведение.
## prompts

=== id: github-cammarasana123-llm-survival-game
title_en: LLM Survival Game (открытый код и логи трёхагентной игры)
title_ru: LLM Survival Game: открытый код и логи трёхагентной игры
## summary
В открытой трёхагентной игре на выживание (survival) опубликованы 80 запусков: состав моделей и память варьируются, журналы сохраняют приватные сообщения и обязательства (commitments).
## design
Каждый запуск включает трёх агентов в условиях дефицита ресурса (scarcity), где выжить могут только два; участники обмениваются приватными текстовыми сообщениями, обновляют порядковое relational-состояние (ordinal relational state) и могут заключить коалицию для исключения третьего. Дизайн 2×2 скрещивает однородный и гетерогенный состав моделей с отсутствием памяти или цепочечной памятью (chain memory); по 20 запусков в каждом условии. Агенты отображаются нейтрально как Agent A/B/C; в смешанном условии соответствие бэкенда (backend) и видимого имени рандомизируется. Запуск завершается, когда два агента сообщают как минимум explicit_commitment к одной цели исключения. Репозиторий предоставляет датасет из 80 запусков (80-run), логи по ходам и события обязательств (commitment).
## tech
Основной запускающий скрипт (main runner) `code/run_experiment.py`, анализ и графики `code/make_figures.py`; CSV включают сводки (summaries), записи по ходам (turn records), события сообщений (message events), события обязательств (commitment events), использование токенов (token usage) и предупреждения валидации (validation warnings). Есть десять пакетов (batches) с конфигами, завершением и таблицами анализа; публичные json/jsonl логи. Поддерживаются тестовый запуск без API (mock run) и реальные вызовы к Groq/Cerebras (README требует ключи в переменных окружения (env), плюс модели и условия могут использовать другие бэкенды из configs). Отдельная роль модератора (moderator) обслуживает запуски с цепочечной памятью (chain-memory runs), пишет сводки в память; нейтральные подписи скрывают модели.
## prompts
По README промпты (prompts) и валидированные обновления состояния, сообщения, исходы, fallback/parse и использование токенов находятся в открытых логах; вход и выход модератора (moderator input/output) представлены отдельно. Видимые модели скрыты во время игры; ordinal commitment — самоотчёт протокола, а не прямое наблюдение внутреннего намерения. Для точных промптов и моделей смотреть конфигурацию эксперимента по каждому пакету (per-batch experiment_config) и логи, а не только README.
## costs
В README заявлено наличие token_usage.csv; конкретная общая цена здесь не пересчитывается. MOCK-запуск не использует API; деньги из игрового ресурса не смешиваются с API-затратами. Доступный README не приводит унифицированного счёта.
## results
README сообщает размер корпуса (80 запусков), 20 на каждое из четырёх условий и наличие агрегированных таблиц и трасс. Полные численные результаты нужно брать из CSV и аналитических таблиц; README не сообщает сводного эффекта памяти и гетерогенности, поэтому не приписываю победившее условие. Запуски используют разные бэкенды и конфигурации, а провайдеры предупреждают о недетерминизме; точная реплика не гарантирована.
## conclusions
Репозиторий — полезный открытый источник для наблюдения коалиций, обещаний, исключения и влияния памяти в конкретной ограниченной игре. Данные дают проверяемые трассы, но сами по себе не свидетельствуют о реальной дружбе или длительном обществе.
## limits
Роли, дефицит ресурса (scarcity), правило двух выживших, скрытость бэкенда и порог завершения заданы; обязательства (commitments) структурированы как самоотчёт. 20 запусков на клетку — ограниченное число, а провайдеры меняют модели. Люди отсутствуют; результат зависит от промпта и сценария.
