title_en: tsinghua-fib-lab/AgentSociety

## summary
Фреймворк Университета Цинхуа для симуляций LLM-агентов в городской и исследовательской среде: v1 — крупномасштабный городской симулятор, v2 — LLM-нативная платформа для социальных наук.
## key_findings
- README разделяет два пакета: AgentSociety 2 (рекомендован; LLM-нативная платформа с маршрутизаторами рассуждения CodeGen, ReAct, Plan-Execute, Two-Tier и Search) и AgentSociety 1.x (устаревший вариант, legacy; городская симуляция с Ray и gRPC).
- У v2 заявлены исследовательские навыки: поиск литературы, генерация гипотез, дизайн эксперимента и написание статьи, а также воспроизведение экспериментов через JSONL-replay и DuckDB.
- У v1 в README перечислены городская симуляция (мобильность, экономика, социальный модуль), распределённые вычисления на Ray и многоагентная координация с коммуникацией.
- Требования по README: Python 3.11 и выше и ключ API LLM (OpenAI, Anthropic или любой провайдер через litellm); пример задаёт модель через переменную AGENTSOCIETY_LLM_MODEL = gpt-5.5.
## agents
не опубликовано в README (в примере один агент; заявлены городские масштабы в v1)
## design
Из README следуют два различных проектных подхода. AgentSociety 2 — платформа для исследовательских экспериментов с LLM-агентами: агенты объявляются как метаданные (спецификации с id, профилем и конфигурацией), а класс society создаёт их рабочие пространства при init(). Среда собирается из модулей (например, SimpleSocialSpace из contrib.env), управляемых маршрутизатором (CodeGenRouter по умолчанию). Агенты описываются как «stateless records» (записи без собственного состояния), которыми управляют Ray Tasks, с клиентами среды, LLM, трассировки и replay через единый ServiceProxy. AgentSociety v1 задуман как крупномасштабный городской симулятор: мобильность, экономика, социальный модуль, распределённое выполнение на Ray и интеграция через gRPC. В README не указаны протоколы экспериментов, контрольные условия, метрики, число агентов в исследованиях, порядок ходов по умолчанию и результаты валидации. Тексты статей arXiv:2607.11895 и arXiv:2502.08691 в проверенный текст не входили.
## tech
Установка: pip install agentsociety2 (v2) и pip install agentsociety (v1). Требуется Python 3.11 и выше. LLM настраивается переменными окружения AGENTSOCIETY_LLM_API_KEY, AGENTSOCIETY_LLM_API_BASE (пример: https://api.openai.com/v1) и AGENTSOCIETY_LLM_MODEL (пример: gpt-5.5). Заявлены также клиенты провайдеров litellm. Архитектура v2: маршрутизаторы рассуждения (CodeGen по умолчанию, ReAct, Plan-Execute, Two-Tier, Search), подключаемые на ходу инструменты среды (hot-pluggable), MCP-интеграция, Ray Tasks для параллельного выполнения, DuckDB для чтения трасс, JSONL-каталог для replay. Структура репозитория: packages/agentsociety2 (v2), packages/agentsociety (v1), agentsociety-community, agentsociety-benchmark, frontend (React), extension (VSCode), examples для v2 (basics, games, advanced). Версии пакетов и значения по умолчанию для параметров, кроме перечисленных, в README не указаны. Память, коммуникация и расписание ходов на уровне конкретных агентов в README подробно не раскрыты.
## prompts
В README не опубликованы тексты системных промптов агентов или маршрутизаторов. Пример вызова: society.ask("What's your name?"). Шаблоны и инструкции по умолчанию для маршрутизатора CodeGen следует искать в исходном коде packages/agentsociety2; в проверенном тексте их нет, поэтому точный шаблон времени выполнения (runtime) не восстанавливается.
## costs
README не публикует расходов, токенов или тарифов. Упомянутые переменные окружения указывают на доступ к внешнему LLM API, но сумм или расчётов стоимости симуляций нет: не опубликовано.
## results
В README нет экспериментальных результатов по поведению агентов, валидации или сравнению с эмпирическими данными. Публикации arXiv:2607.11895 (v2) и arXiv:2502.08691 (v1) указаны как основные источники; их результаты здесь не приписываются, поскольку полный текст не проверялся.
## conclusions
Авторы README заявляют, что AgentSociety 2 предназначен для социальных наук и исследовательских экспериментов, а v1 — для городского масштаба. Это назначение, а не эмпирический вывод.
## limits
Версия v1 описывает городское моделирование и не является микроуровневой платформой для малых групп; v2 рекомендован, но в README нет статистики использования и валидации. Зависимость от внешних LLM API и версии модели. Сравнение с задачами стенда на примерно 20 агентов требует отдельной оценки сложности установки и стоимости (вне данного источника). Лицензия Apache-2.0 не распространяется на папку commercial в v1.

## summary
MARBLE — кодовый каркас MultiAgentBench для кооперативных и состязательных сред, с общей памятью (shared memory) и расширяемыми агентами и интеграциями.
## design
README описывает MultiAgentBench как фреймворк для взаимодействия LLM-агентов в разных симулированных средах — с кооперативным или конкурентным поведением, когнитивными способностями и коммуникационными механизмами. Модули позволяют заменять агента, среду и модельный бэкенд, задавать иерархическое и кооперативное исполнение (hierarchical/cooperative execution), общую память и метрики. Опубликованный README не содержит полной схемы бенчмарка; для дизайна и задач бенчмарка следует обращаться к статье arXiv:2503.01935. Пример кода запускает Werewolf через scripts/werewolf, однако это лишь один сценарий из общей платформы.
## tech
Репозиторий рассчитан на Python 3.10, Poetry, Docker (опционально) и переменные OPENAI_API_KEY и Together_API_KEY. Приводятся команды установки и примеры; в `examples` запускается симуляция Werewolf. В статье цитируется Kunlun Zhu et al. (2025), MultiAgentBench: Evaluating the Collaboration and Competition of LLM agents. README содержит общую информацию о модульном дизайне (modular design), а полные configs, models и metrics следует сверять по статье и коду.
## prompts
README не содержит полного списка всех промптов; системные инструкции и роли находятся в сценариях и коде. Общая возможность общей памяти не гарантирует, что каждый бенчмарк использует одинаковую память.
## costs
Общий счёт API и количество токенов не указаны; стоимость зависит от выбранных API LLM и числа вызовов. Docker и настройка окружения — инфраструктура, а не цена API.
## results
README репозитория не публикует численных результатов исследования. Он подтверждает доступность фреймворка, скриптов окружения и метрик; ему не приписываются ключевые оценки (headline scores) из arXiv.
## conclusions
MARBLE даёт открытую платформу для многоагентной координации и соревнования, где архитектуры и среды можно заменять. Социальные утверждения следует ссылать на эмпирическую статью или конкретный протокол, а не на общие утверждения о возможностях.
## limits
README — краткое описание и установка; нет независимой оценки качества, полного архивирования промптов или стоимости. Гибкость фреймворка увеличивает число параметров, которые нужно фиксировать для репликации. Результаты привязаны к конкретной версии бенчмарка (benchmark release).

=== id: github-ybkim95-agent-scaling
title_en: Agent Scaling (code and artifacts for «Capable language models can outgrow the benefits of collaboration»)
title_ru: Agent Scaling: код и артефакты к статье «Capable language models can outgrow the benefits of collaboration»
## summary
Официальные артефакты к статье в Nature Machine Intelligence о том, когда рост возможностей модели уменьшает выигрыш от мультиагентного сотрудничества (multi-agent collaboration).
## design
README связывает код со статьёй в Nature Machine Intelligence «Capable language models can outgrow the benefits of collaboration» и препринтом «Towards a science of scaling agent systems». Бенчмарки: BrowseComp-Plus, PlanCraft, SWE-bench Verified, Terminal-Bench, Workbench и Finance Agent; сравнимые конфигурации: одиночный агент (single-agent), централизованная команда с лидером (centralized team with lead), децентрализованная одноранговая (decentralized peer-to-peer), гибридная (hybrid) и независимые агенты (independent agents). Число агентов настраивается для централизованного режима; задачи включают вопросы-ответы с многошаговым поиском (web/multi-hop QA), планирование в Minecraft (Minecraft planning), программные задачи (software issues), работу в терминале (terminal), бизнес-инструменты и финансы. Это системный бенчмарк масштабирования агентов, а не наблюдение за долгосрочной культурой или дружбой.
## tech
Python 3.11 и выше, `uv`, конфигурации Hydra; API через провайдеров, совместимых с LiteLLM: OpenAI, Gemini, Anthropic. README советует фиксировать (pinning) версию релиза: рукопись цитирует тег v2.1.3, версия v2.2.x исправляет скрипты анализа. Типы мультиагентности указаны в конфигурациях; конвейер записывает полную конфигурацию запуска, логи, промпты, ответы и вызовы инструментов, результаты по каждому экземпляру и метрики. Два датасета требуют скриптов загрузки; SWE-bench и Terminal-Bench требуют Docker. Модели, указанные в README: варианты GPT-5, Gemini 2.5 и 2.0, Claude Sonnet 4.5, 4 и 3.7 (старые версии имеют ограничения по бэкенду).
## prompts
Промпты и конфигурации задают рабочие процессы одиночного и мультиагентного режимов, инструменты и задачи; пример запуска сам по себе не раскрывает все промпты. Лог может сохранять сообщения, вызовы инструментов и выбранные параметры; их нужно анализировать как спецификацию экспериментального агента.
## costs
README не публикует суммарной стоимости API; сравнения по вычислениям и качеству, а также журналирование использования (usage logging) есть в экспериментальных артефактах, но автоматически в денежную сумму они не переводятся. Один вызов на агента не фиксирован для всех задач.
## results
README устанавливает связь с опубликованной статьёй и предоставляет конвейер для получения результатов, но не содержит полноценной таблицы эффектов. Главное утверждение самой журнальной статьи — сильные модели могут превысить выгоды сотрудничества; численные результаты следует брать из статьи, а не из README. Версия v2.2.x исправляет скрипты анализа относительно тега, указанного в рукописи, поэтому результаты зависят от коммита.
## conclusions
Артефакты полезны для воспроизведения границ, в которых масштабирование мультиагентного тестирования (multi-agent test-time scaling) даёт пользу или проигрывает мощной одиночной модели. Необходимо фиксировать набор данных, архитектуру, модель, число агентов и версию кода.
## limits
Различия задач и моделей, а также централизованных и децентрализованных конвейеров затрудняют атрибуцию. Несколько датасетов нужно скачивать отдельно; версии и конечные точки (endpoints) могут исчезнуть. Это бенчмарк производительности на задачах, а не оценка социальной нормы.
