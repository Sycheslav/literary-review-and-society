## Короткая аннотация

PillagerBench — real-time Minecraft benchmark для team-vs-team конкуренции с двумя сценариями и встроенными rule-based противниками. Авторы предлагают TactiCrafter, который в ходе повторных эпизодов генерирует человекочитаемые тактики, обновляет причинную модель мира и строит модель тактики соперника. Система сравнивается с random и CoT baseline; задача тестирует распределение работы, адаптацию и adversarial planning в среде, а не только кооперацию внутри одной команды.

## Дизайн исследования

Оба сценария поддерживают две команды по два агента, например Ryn/Raze и Byte/Blink; агенты должны сотрудничать внутри команды, одновременно мешая сопернику. Mushroom War — временно ограниченная схватка за gathering/farming ресурсов; Dash & Dine включает готовку/доставку и динамические причинные зависимости в мире. Benchmark включает Minecraft server, отдельный Mineflayer process на агента, Bridge API и Environment module; common phases pre-game (scenario metadata, initial state), game (наблюдения и доступ к управляемым actions), post-game. Конфигурации YAML/Hydra фиксируют episodes, сценарии и policies, Docker повышает воспроизводимость, каждая среда логируется. ТactiCrafter формирует tactics на эпизод, раздаёт субзадачи двум teammate-ам, анализирует event log и использует общую causal graph и inferred enemy tactic в следующем эпизоде. Основные метрики — команда points, очки, отнятые у оппонента, point difference и win rate; дополнительно response time, output tokens, tokens/second и число code rollout iterations, важные в real-time Minecraft. Кейс-анализ после 20 self-play эпизодов показывает адаптацию стратегии (в том числе приоритет высокодоходных культур и counter-tactics), но также реальные ошибки исполнения: неверное условие проверки sweet berries, неудачная перепосадка урожая, задержки при сигналинге. Таким образом, benchmark измеряет командное исполнение под ресурсными и противниковыми ограничениями, а не “свободное общество” агентов.

## Техническая реализация

TactiCrafter состоит из Tactics Module, Causal Model, Opponent Model и Base Agents. Tactics module использует zero-shot CoT для первоначального плана; затем few-shot CoT обновляет план с учётом событий прошлого эпизода. Causal graph извлекается LLM из control primitives/scenario description в JSON, обновляется после каждого эпизода; Opponent Model классифицирует наблюдаемую тактику adversary. Base Agents генерируют исполняемый JavaScript через Mineflayer, получают feedback по execution errors и self-critique о выполнении общего плана. System object сохраняется между episodes. Репозиторий `aialt/PillagerBench` предоставляет среду и код. В статье модели/аппаратные детали описаны в §V-A и Appendix; стоимость в долларовом виде не раскрыта.

## Промпты и инструкции

Методический §IV и текст приложения описывают тактические, causal discovery, opponent modeling, action code и critic prompts; схема включает zero-shot и few-shot CoT. Prompting задаёт цель команды и контекст текущей карты, а tactics явно распределяют роли/субзадачи, значит эффективность нельзя приписывать спонтанному самоназначению ролей. Логи и generated code позволяют сравнивать намерение с фактическим выполнением.

## Опубликованные расходы и вычисления

Статья сообщает среднее время ответа, число выходных токенов, tokens/sec и rollout iterations как показатели real-time performance; агрегированные API dollars/общий токен-бюджет в проверенном тексте не приведены. Использование built-in script opponents не означает API расходы.

## Результаты

Авторы сообщают, что TactiCrafter превосходит random и прямой zero-shot CoT baselines по конкурентным метрикам и адаптируется в повторном self-play (§V-C/D). Через 20 self-play эпизодов causal graphs воспроизводят значительную часть зависимостей, хотя извлечение из chat log даёт неоднозначные графы: например, count в action upper bound не совпадает с реально mined blocks; многие причины/эффекты связаны лишь с текущим inventory и пусты (§V-E). Кейс эпизодов показывает стратегическую адаптацию, но успешность зависит от кодовой надёжности: команды могут иметь преимущество и потерять урожай из-за багов исполнения, пропустить ресурс или тратить ходы на избыточные сигналы. Поэтому результат включает одновременно улучшение tactics и bottleneck фактического control code.

## Выводы авторов

Авторы предлагают PillagerBench как воспроизводимую конкурентную среду для командных LLM-систем и TactiCrafter как модульную схему повторного обучения тактикам через рефлексию/logs. Вывод о self-play learning ограничен этой игрой и явно заданной high-level tactics architecture.

## Ограничения и интерпретация

Minecraft-тактики, встроенные scenarios и rule-based opponents не покрывают open-ended social norms. Каждая команда — два агента с общей постановкой и распределённым планом; humans absent. Извлечённая causal graph может ошибочно интерпретировать event logs; generated code может fail несмотря на разумный план. Real-time API latency оказывает прямое влияние на игру, поэтому сравнение model family зависит от provider/serving. При переносе нужны точные versions/configs из YAML и не только headline win rate.
