## Коротко

> Открытая библиотека Google DeepMind для построения генеративных агентных симуляций, где Game Master (GM) разрешает действия агентов в языковой среде.

- **Значимость для обзора:** ключевая — Прямо предназначена для моделирования взаимодействий агентов в социальной среде и поддерживает сценарии с правилами, ролями и памятью; ключевой инструмент для стенда лаборатории, хотя сама библиотека не даёт эмпирических выводов.
- **Число агентов:** не опубликовано (зависит от сценария; в README приведён пример с четырьмя персонажами)
- **Ключевые слова:** Concordia, Game Master, generative social simulation, entity-component, associative memory, LLM agents

**Главные результаты**

1. Concordia описана в README как библиотека для построения и запуска генеративных агентных моделей; сущности (entities) действуют на естественном языке, а Game Master переводит их намерения в исходы.
1. Архитектура состоит из сущностей, компонентов (инструкции, память, выбор действия), префабов (шаблонов), движка run_loop и интерфейсов среды (пошаговая, одновременная или асинхронная).
1. Из README: модельно-агностичность; нужен LLM API и провайдер эмбеддингов для ассоциативной памяти. Качество результатов зависит от выбранной модели.
1. Пример в README: четыре друга в заваленном снегом пабе, спор из-за разбитой машины; агенты рассуждают по схеме March and Olsen (2011) из трёх вопросов о ситуации, о себе и о том, что делает такой человек в такой ситуации.

## Короткая аннотация

> Консолидировано из прежних обзоров; приведённые здесь детали и числа отдельно по первоисточнику не подтверждены.

Специально создан для generative social simulation. Есть агенты, компоненты памяти, simulation engine и Game Master, который формализует последствия действий в физической/социальной/цифровой среде. Работает с обычным LLM API. 

Для публикационной серии Лаборатории №57 я бы в конечном итоге выбрал именно этот путь, используя CAMEL/Concordia как источник компонентов

## Дизайн исследования

Concordia моделирует среду через Game Master (GM): эта сущность симулирует мир, в котором взаимодействуют игроки (player entities). Игроки описывают намерения на естественном языке, а GM переводит их в исходы, проверяя, например, физическую правдоподобность в симулированном мире. Роли назначаются на каждый вызов run_loop: движок запрашивает действия у игроков и наблюдения у GM. Среда может быть устроена по-разному: в каталоге concordia/environment перечислены движки, которые определяют очерёдность ходов, одновременные действия или асинхронные действия. В README не приведены конкретные сценарии исследований, число участников по умолчанию, протокол измерения исходов и контрольные условия. Пример с четырьмя друзьями в пабе (ссылка на Colab-тьюториал) показывает агентов, которые используют схему трёх вопросов о ситуации, о собственной личности и о нормативном поведении. Этот пример иллюстративный; результаты в README не приводятся.

## Техническая реализация

Установка из PyPI (gdm-concordia) или в режиме разработки (pip install --editable .[dev]); тесты через pytest. Для LLM нужен API, поддерживающий выборку текста; дополнительно для ассоциативной памяти нужен текстовый эмбеддер фиксированной размерности. Компоненты: память (ассоциативная), сенсорные модули, инструкции, выбор действия; префабы — предсобранные конфигурации сущностей, которые переопределяются параметрами имени, инструкций и цели. Каталоги: concordia/prefabs, concordia/components, concordia/environment (интерфейсы движка), concordia/document (управление промптами и контекстом), concordia/language_model (обёртки API), examples/. Есть GUI и CLI для редактирования симуляции (ссылка на руководство по сущностям и компонентам). В README упоминаются дополнительные зависимости для Google-провайдеров (pip install .[google]). Версия библиотеки и конкретные модели по умолчанию в README не указаны; их следует сверять с релизами в репозитории.
