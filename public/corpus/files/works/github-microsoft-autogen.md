## Короткая аннотация

AutoGen — фреймворк для составления LLM-систем из настраиваемых агентов, инструментов и автоматических диалогов. Документация разделяет низкоуровневое event-driven message passing/runtime и более высокоуровневые AgentChat топологии, включая групповые чаты. В качестве источника проект важен для воспроизводимого управления коммуникацией и инструментами, а не как самостоятельное доказательство, что модельная группа спонтанно сотрудничает.

## Дизайн исследования

README описывает модульную архитектуру: Core API содержит определения агентов, передачу сообщений, событийный локальный/распределенный runtime и поддержку .NET/Python; AgentChat дает ориентированный на прототипирование интерфейс, включая двухагентный диалог и group chat; Extensions связывают модельные клиенты (например OpenAI/Azure OpenAI), исполнение кода и инструменты. AutoGen Studio — GUI, AutoGen Bench — набор для оценки. Magentic-One приводится как пример команды, построенной поверх AgentChat/Extensions и способной работать с web browsing, code execution и файлами. Это описание возможностей upstream, не независимый benchmark результата.

## Техническая реализация

Репозиторий разделяет python workspace на `autogen-core`, `autogen-agentchat`, `autogen-ext` и `autogen-studio`. Документация дает инструменты для заданных ролей/специализаций, маршрутизации сообщений и кода; состав топологии конфигурируется разработчиком. README, просмотренный 27.10.2026, говорит “archived and no longer maintained by Microsoft”, рекомендует Microsoft Agent Framework новым проектам, а AutoGen характеризует как community-managed. Это актуальный статус ветки; не следует отождествлять его с прежней стадией active research framework.

## Промпты и инструкции

System messages и сообщения ролей определяет создатель приложения; общие README/FAQ дают примеры и назначения, но не единый исследовательский prompt. Для анализа социальности необходимо хранить версию шаблона, правила хода, лимиты инструментов и состояние диалога, поскольку фреймворк позволяет это задавать, но не навязывает.

## Опубликованные расходы и вычисления

Официальный README не публикует единого API-бюджета или токен-стоимости. Расход зависит от подключенного провайдера, модели, длины диалога и вызовов инструментов; здесь он не оценивается.

## Результаты

Набор возможностей и границ взят из официальной документации; никакого числа «успешности кооперации» для самого AutoGen карточка не приписывает. Рекомендация перейти на Agent Framework относится к поддержке инструмента, а не к научному сравнению архитектур.

## Выводы авторов

AutoGen полезен как воспроизводимая оркестрационная инфраструктура: он делает видимыми архитектуру сообщений, роли и обмен с инструментами. Для литературы его надо цитировать как software, а эмпирические результаты брать из отдельных работ, использующих его.

## Ограничения и интерпретация

Платформа допускает много вариантов архитектуры; результат проекта не задает каузальное преимущество group chat или конкретной топологии. Текущий репозиторий в режиме archive/community maintenance; сохранность, зависимости и миграционные различия требуют фиксации commit/version. Агентные «роли» создаются системными сообщениями и не доказывают устойчивые личные свойства.
