# Concordia: библиотека генеративных агентных симуляций

**Оригинальное название:** Concordia: A library for generative social simulation  
**Авторы и год:** Alexander Sasha Vezhnevets, John P. Agapiou, Avia Aharon, Ron Ziv, Jayd Matyas, Edgar A. Duéñez-Guzmán, William A. Cunningham, Simon Osindero, Danny Karmon, Joel Z. Leibo; 2023 (по BibTeX в README; технический отчёт arXiv:2312.03664).  
**Тип и статус публикации:** открытая программная библиотека (репозиторий GitHub, пакет gdm-concordia на PyPI), не научная статья.  
**Оригинал:** [репозиторий google-deepmind/concordia](https://github.com/google-deepmind/concordia). Снимок README получен 29.10.2026.  
**Прочитанный источник:** README репозитория по сохранённому снимку [readme-source.md](readme-source.md). Исходный код, примеры и технический отчёт arXiv:2312.03664 не открывались, поэтому изложение описывает инструмент, а не эмпирическую работу.

## Аннотация

Concordia — открытая библиотека из репозитория google-deepmind (README: «не официально поддерживаемый продукт Google») для построения агентных симуляций, в которых генеративные агенты описывают действия обычным языком, а отдельная сущность Game Master моделирует среду и выносит последствия. Библиотека строится из сущностей, компонентов, префабов и движка run_loop. Она поддерживает пошаговые, одновременные и асинхронные среды и работает с любым LLM API и эмбеддером для ассоциативной памяти. README приводит учебный пример: четыре друга в заснеженном пабе спорят о разбитом автомобиле, а агенты выбирают действия по схеме трёх вопросов. Количественных результатов, метрик и контрольных условий в README нет. Главная оговорка: поведение зависит от выбранной модели и от Game Master, который сам задаёт исход, поэтому библиотека сама по себе не доказывает ничего о социуме.

## Главные результаты

- Архитектура строится из сущностей (entities) с компонентами: инструкциями, памятью и выбором действия. Префабы — параметризуемые шаблоны, а роли player и GM назначаются на каждом вызове run_loop (README, § How it Works).
- Пакет environment задаёт интерфейсы движка с пошаговым, одновременным и асинхронным действием (README, § Folder Structure).
- Для работы нужны LLM API, поддерживающий выборку текста, и эмбеддер фиксированной размерности для ассоциативной памяти. README прямо указывает, что качество результатов зависит от модели (README, § Bring your own LLM).
- Пример с четырьмя агентами иллюстративен: в README он не сопровождается ни метриками, ни контрольными условиями (README, § Example usage).

## 1. Что проверяли

Concordia отвечает на инженерный вопрос: как собрать симуляцию, в которой генеративные агенты действуют в физической, социальной или цифровой среде и получают последствия своих действий. README не формулирует гипотез и не заявляет эмпирических результатов (README, § About). Заявленные области применения — социальные науки, безопасность и этика ИИ, когнитивная нейронаука, экономика, синтетические данные для персонализации и тестирование сервисов (README, § About).

## 2. Агенты, среда и исходные условия

Агент — сущность, собранная из компонентов. Роли игрока и мастера игры (GM) назначаются в вызове run_loop, а не закреплены за типом агента (README, § How it Works). Среда может быть физической, социальной или цифровой. GM проверяет правдоподобие действий и формирует наблюдения (README, § About). Исходные условия задаёт автор симуляции: инструкции, память, цель и набор компонентов.

В примере агенты построены по схеме March и Olsen (2011): что это за ситуация, кто я и что делает такой человек в такой ситуации (README, § Example usage). Схема задаёт идентичность и нормы заранее, а не даёт им возникнуть в ходе симуляции.

## 3. Метод

Симуляция собирается так: выбирается префаб, его параметры (имя, инструкции, цель) переопределяются, из компонентов собирается сущность, затем задаются среда и цикл исполнения. На каждом шаге игроки выдают действия на естественном языке, GM возвращает наблюдения и разрешает последствия, после чего контекст обновляется (README, § How it Works). Управление промптами и контекстом вынесено в отдельный модуль (README, § Folder Structure). Ассоциативная память строится на эмбеддингах (README, § Bring your own LLM). Установка выполняется через PyPI (gdm-concordia) или из исходников, тесты запускаются через pytest (README, § Installation, § Development).

## 4. Дизайн эксперимента и метрики

README не задаёт стандартного числа агентов, метрик, базовых условий и числа прогонов: это библиотека-конструктор (README, § About). Автор симуляции сам фиксирует модель мира, протокол действий, память, промпты, число прогонов и исход. Без версий префабов, конфигураций компонентов и настроек GM нельзя отделить эффект модели от эффекта сценария и правил разрешения действий. Этот вывод следует из структуры README, он не сформулирован в самом тексте.

## 6. Что следует из результатов и чего не следует

Из README следует, что Concordia — программный каркас для агентных симуляций, в котором намерение агента и исход разделены прослойкой Game Master. Это удобно для аудита, но GM одновременно становится источником смещения: его интерпретация задаёт исход (README, § How it Works).

Не следует, что библиотека воспроизводит социальные нормы, дружбу или институты: README описывает назначение и не приводит проверок поведения агентов (README, § About). Не следует приписывать результаты «самому социуму», если разрешение действий и наблюдения контролирует центральная сущность. Пример с пабом тоже не доказывает возникновения дружбы: в README агенты заданы друзьями.

## 7. Ограничения и воспроизводимость

README предупреждает, что результаты зависят от модели. Нужны внешний LLM API и эмбеддер, а модель, провайдер, контекст и настройки GM следует фиксировать (README, § Bring your own LLM). Версия библиотеки и модели по умолчанию в README не указаны, поэтому повторение требует выбрать конкретный релиз (README, § Development). Сведения о релизе v2.4.0, которые приводит программа исследований лаборатории, в этом тексте не проверялись.

Стоимость в README не указана: она зависит от выбранного провайдера API. Ссылку на design-pattern статью arXiv:2507.08892 README даёт в заголовке. Её утверждения здесь не проверялись. Дисклеймер README указывает, что это не официальный продукт Google (README, § Disclaimer).

## 8. Значение для Лаборатории № 57 и «Верхума»

*Предложения редакции обзора, а не авторов статьи.* Concordia может стать каркасом прототипа лабораторной среды с раздельными журналами агентов и среды. Агент предлагает действие, GM проверяет его по правилам механизма, журнал фиксирует принятое решение. Роль GM совпадает с ролью центра в теории активных систем. Её можно менять и измерять: что знает центр, кто наблюдает решения и кто задаёт допустимость действий. Для «Верхума» такой слой нужен, чтобы отличать реальное согласование участников от исхода, который произвёл симулятор.
